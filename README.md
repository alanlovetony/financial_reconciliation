# 财务对账工具 💰

一个基于 Streamlit 和 Pandas 开发的财务对账系统，用于逐笔核对银行流水与有益云系统数据。

## ✨ 功能特点

- 📋 **逐笔核对**: 每笔银行流水单独一行，清晰对比匹配结果
- 🔄 **智能识别**: 自动根据捐赠说明区分 T+1 和 T+N 数据
- 🎯 **精确匹配**: 金额必须完全相等才算匹配成功
- 📊 **现代化UI**: 渐变色卡片、悬浮动画、响应式设计、自定义标签页
- 💾 **导出功能**: 表格右上角一键导出 CSV/Excel 格式
- 📈 **交易统计**: 显示每笔匹配的交易笔数
- 📅 **每日汇总**: 按日期范围查看各项目捐赠统计

## 📖 使用方法

1. 启动应用：
```bash
streamlit run financial_reconciliation_simple.py
```

2. 在浏览器中打开显示的 URL (通常是 http://localhost:8501)

3. 上传两个数据文件：
   - **有益云数据**: 直接从有益云系统导出的 Excel/CSV 文件
   - **银行流水**: 银行导出的流水文件

4. 点击"开始对账"按钮

5. 查看对账结果：
   - **逐笔核对**: 每笔银行流水的匹配结果
   - **未匹配**: 银行有流水但系统没有对应业务
   - **未到账**: 系统有业务但银行没收到钱
   - **项目明细**: 项目×日期的金额透视表
   - **每日汇总**: 按日期范围查看各项目统计

6. 使用表格右上角的下载按钮导出数据

## 🎯 对账规则

### 数据分类
系统会检查 `捐赠说明` 字段：
- 包含 `GFYH` → **T+N**（广发银行广发易汇收款）
- 不包含 `GFYH` → **T+1**（其他收款渠道如微信小程序等）

### 匹配逻辑

**以银行到账日期为主线，逐笔核对：**

1. **T+1 匹配**（不带GFYH的业务）
   - 银行到账日期 - 1天 = 业务日期
   - 例：12/2到账 → 匹配12/1的T+1业务
   - 特殊处理：附言包含"968"的识别为月捐汇总

2. **T+N 匹配**（带GFYH的业务）
   - 优先从银行附言/用途中提取业务日期
   - 如：附言 `1201_xxx` → 匹配12/01的业务
   - 若无法提取，则倒查过去30天

3. **匹配条件**
   - 金额必须**完全相等**才算匹配成功

## 📋 数据格式要求

### 有益云数据
直接从有益云系统导出即可，系统会自动：
- 跳过第一行（汇总信息行）
- 根据 `捐赠说明` 字段自动识别 T+1 和 T+N

必须包含的列：
| 捐赠项目 | 捐赠时间 | 捐赠金额 | 捐赠说明 |
|---------|---------|---------|---------| 
| 项目A   | 2024-01-01 10:30:00 | 1000.00 | 【GFYH】微信捐款... |
| 项目B   | 2024-01-01 14:20:00 | 2000.00 | 【微信小程序】捐款... |

### 银行流水数据
| 发生时间 | 收入 | 用途 | 附言 |
|---------|------|------|------|
| 2024-01-03 | 3000.00 | 银联入账 | 0101_1573... |
| 2024-01-04 | 5000.00 | 收单入账 | 20240102至20240102... |

## ❓ 常见问题

**Q: 为什么有些银行流水没有匹配上？**
A: 可能原因：
- 有益云系统中没有对应的业务记录
- 金额不完全一致（必须完全相等）
- 这笔款项来自其他渠道（如线下转账）

**Q: 什么是"交易笔数"？**
A: 这是匹配到的业务日期在有益云系统中包含的捐赠笔数。例如12/1有11笔捐赠，汇总金额1962.88，则交易笔数显示为11。

**Q: 如何处理未匹配的银行流水？**
A: 
- 检查银行附言中的日期信息
- 在有益云系统中手工查找对应业务
- 可能是其他渠道的收款，需要单独核对

**Q: 支持哪些文件格式？**
A: 支持 CSV、XLS、XLSX 格式

**Q: 如何使用每日汇总功能？**
A:
1. 切换到"每日汇总"标签页
2. 选择开始日期和结束日期
3. 点击"查询统计"按钮
4. 查看项目汇总表
5. 使用表格右上角的下载按钮导出数据
